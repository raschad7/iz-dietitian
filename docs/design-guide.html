05 / RULES

The rules that keep the system coherent

These are the everyday checks to use when designing a new screen or component.

Use semantic tokens

Use primary, card, muted, border, and status tokens. Do not add raw brand hex values inside UI components.

Action color has meaning

Olive signals something the user can act on. Do not make every chart, card, and control olive.

Keep geometry still

Hover changes color, fill, or edge—not size, radius, or position.

RTL is native

Use logical start/end alignment. Mirror only arrows and other truly directional icons.

Design for touch

Controls are normally 48px high. Compact 40px controls are for dense pointer-only desktop situations.

Respect attention

Use one or two state badges per screen. Clay is for medical/destructive meaning; amber is for attention, not failure.

Cards are structure

Do not nest shadowed cards. A nested item is a quiet tile, not another floating surface.

Fields remain neutral

Fields use a neutral resting state, olive on hover/focus, and validate on blur—not while someone is typing.

Motion is quiet

Use the single sweep easing and short transitions. Respect reduced-motion preferences.
