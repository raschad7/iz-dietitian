# Clinic Onboarding and Profile Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Require newly created staff clinics to enter complete clinic, per-day schedule, and professional-profile data before using the app, keep that data editable from Profile, and repair or precisely diagnose the password-sign-up verification-email path.

**Architecture:** Add a normalized seven-row clinic schedule and completion/contact fields, then expose them through a clinic-scoped `clinic-profile` feature. A focused `/[locale]/onboarding` route and `/[locale]/app/profile` reuse the same field groups; booking resolves the schedule row for the candidate date while week rendering uses a shared envelope. Email work begins with systematic reproduction and transport-level tests so configuration is not mistaken for a code defect.

**Tech Stack:** Next.js 16 App Router, React 19 server actions, TypeScript 5, Drizzle ORM/PostgreSQL, Zod 4, next-intl, Better Auth, Resend, Bun tests, Tailwind/Qiwam semantic tokens.

## Global Constraints

- Work only in `C:\Users\ASUS\.codex\worktrees\dietitian_software-on-boarding` on branch `on-boarding`.
- Do not read, stage, reset, switch, or modify the other agent's `drop-meal-plans-and-foods` checkout.

- Use semantic design tokens, existing `src/components/ui/` primitives, and logical direction utilities for Arabic RTL and English LTR.
- Clinic schedule values use clinic-local wall-clock minutes, weekday `0 = Sunday` through `6 = Saturday`, and 15-minute increments.
- One continuous range per working day; split shifts and date-specific closures remain out of scope.
- No client-portal UI changes. Shared availability code may change only to consume the new schedule correctly.
- No logo/photo upload, biography, services, fees, appointment defaults, or post-onboarding activation flow.
- Preserve existing appointments when schedules change.
- Never add or expose real environment secrets.
- Follow test-driven development for every behavior change and run the Impeccable detector once after UI completion.
