# Changelog

Release notes are generated by GitHub from the pull requests in each release.
The authoritative list is the
[Releases page](https://github.com/raschad7/iz-dietitian/releases); this
file is not maintained by hand.

## How the number is set

The version lives in `package.json` — that is what the app reads at build time
through [`src/lib/version.ts`](src/lib/version.ts) and shows in the settings
footer. Deriving it from a git tag would not survive the build, which does not
get the repository's tags.

[`.github/workflows/release.yml`](.github/workflows/release.yml) raises it when
a pull request merges into `main`, tags the commit, syncs the number back to
`dev`, and publishes generated notes. The bump size comes from a label on the
pull request, not from commit messages:

| Label | `1.2.3` becomes | Meaning |
| --- | --- | --- |
| `release:major` | `2.0.0` | Breaking change |
| `release:minor` | `1.3.0` | New feature, nothing broken |
| *(none)* | `1.2.4` | Fixes and polish |
| `release:skip` | unchanged | Merge without releasing |

## Note on early tags

The current version is **0.4.0**. A `v1.1.0` tag exists from before the
numbering was corrected — it does not represent a later release than `v0.4.0`,
and this file previously claimed a `1.0.0` initial release that was never real.
Treat `v0.4.0` and anything after it as the true line.
